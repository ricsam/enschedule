---
title: "Authentication"
description: "Authenticate to Enschedule with API keys, JWTs, or the dashboard session cookie."
---

Enschedule supports service credentials, user access tokens, and same-origin dashboard sessions.

## API key

Use `X-API-Key` for service-to-service requests:

```bash
curl https://enschedule.example.com/api/schedules \
  --header 'X-API-Key: your-api-key'
```

You may also use the authorization form:

```http
Authorization: Api-Key your-api-key
```

The worker compares this credential with `ENSCHEDULE_API_KEY` and grants administrative service access on a match.

<Warning>
  Treat the API key as a secret. Store it in a secrets manager, send it only over HTTPS, and rotate it when exposure is suspected.
</Warning>

## User login and JWT

Exchange a username and password for an access and refresh token:

```bash
curl --request POST \
  --url https://enschedule.example.com/api/auth/login \
  --header 'Content-Type: application/json' \
  --data '{"username":"admin","password":"replace-me"}'
```

```json
{
  "accessToken": "eyJ...",
  "refreshToken": "eyJ..."
}
```

Send the access token with the `Jwt` authorization scheme:

```http
Authorization: Jwt eyJ...
```

Access tokens expire after 15 minutes. Refresh tokens expire after seven days and rotate when used.

## Refresh a token

```bash
curl --request POST \
  --url https://enschedule.example.com/api/auth/refresh \
  --header 'Content-Type: application/json' \
  --data '{"refreshToken":"eyJ..."}'
```

Persist the returned refresh token and discard the previous one.

## Log out

```bash
curl --request POST \
  --url https://enschedule.example.com/api/auth/logout \
  --header 'Content-Type: application/json' \
  --data '{"refreshToken":"eyJ...","allDevices":false}'
```

Set `allDevices` to `true` to invalidate every stored refresh session for that user.

## Dashboard session

The dashboard backend stores access and refresh tokens in a signed `HttpOnly`, `SameSite=Strict` cookie. Browser JavaScript cannot read the cookie. The backend refreshes an expiring access token and rotates the refresh token.

For production:

- Set `ENSCHEDULE_COOKIE_SESSION_SECRET` to a strong independent secret.
- Set `ENSCHEDULE_HTTPS_ONLY_COOKIES=true`.
- Serve the dashboard only over HTTPS.
- Set `ENSCHEDULE_PUBLIC_ORIGIN` when a reverse proxy changes the public origin.

## Authorization failures

- `401 Unauthorized` means the credential is missing, expired, or invalid.
- `403 Forbidden` means the authenticated identity lacks access to the resource or action.
