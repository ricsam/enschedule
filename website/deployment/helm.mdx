The official Enschedule Helm chart deploys PostgreSQL, a worker, shared log storage, the dashboard, and a migration job to any Kubernetes cluster. Browse released chart versions at [ricsam.github.io/enschedule](https://ricsam.github.io/enschedule).

## Prerequisites

- A running Kubernetes cluster
- [Helm 3](https://helm.sh/docs/intro/install/) installed locally
- `kubectl` configured to target that cluster

## Add the chart repository

```bash
helm repo add enschedule https://ricsam.github.io/enschedule
helm repo update enschedule
```

## Quickstart (evaluation)

<Warning>
  The quickstart command uses ephemeral (non-persistent) storage. Use it for evaluation only — all data is lost when pods restart.
</Warning>

```bash
helm upgrade --install enschedule enschedule/enschedule \
  --namespace enschedule \
  --create-namespace \
  --set database.persistence.enabled=false \
  --set worker.persistence.enabled=false \
  --set storage.enabled=false \
  --wait \
  --timeout 10m
```

Once all pods are ready, forward the dashboard port to your local machine:

```bash
kubectl --namespace enschedule port-forward service/dashboard-service 3000:3000
```

Then open [http://localhost:3000](http://localhost:3000).

## Production values

Pass configuration through a values file rather than on the command line so that secrets are not recorded in your shell history. Create `values-production.yaml`:

```yaml values-production.yaml
config:
  pgPassword: replace-me
  accessTokenSecret: replace-me
  refreshTokenSecret: replace-me
  cookieSessionSecret: replace-me
  apiKey: replace-me
  adminAccount: admin:replace-me
  httpsOnlyCookies: true
  publicOrigin: https://enschedule.example.com

dashboard:
  ingress:
    enabled: true
    className: traefik
    hosts:
      - host: enschedule.example.com
        paths:
          - path: /
            pathType: Prefix

database:
  persistence:
    enabled: true
    storageClass: rook-ceph-block
    accessMode: ReadWriteOnce
    size: 10Gi

worker:
  persistence:
    enabled: true
    storageClass: rook-ceph-block
    accessMode: ReadWriteOnce
    size: 5Gi
    mountPath: /var/log/enschedule
```

Then install or upgrade:

```bash
helm upgrade --install enschedule enschedule/enschedule \
  --namespace enschedule \
  --create-namespace \
  --values values-production.yaml \
  --wait
```

<Tip>
  Use Kubernetes Secrets or an external secrets operator such as [External Secrets Operator](https://external-secrets.io) to inject credentials instead of storing plain text values in `values-production.yaml`.
</Tip>

## Ingress

Enable ingress for the dashboard by setting `dashboard.ingress.enabled=true`. The chart supports any ingress controller — set `dashboard.ingress.className` to match your controller (for example `nginx` or `traefik`).

Configure TLS under the `dashboard.ingress.tls` key:

```yaml
dashboard:
  ingress:
    enabled: true
    className: nginx
    tls:
      - secretName: enschedule-tls
        hosts:
          - enschedule.example.com
    hosts:
      - host: enschedule.example.com
        paths:
          - path: /
            pathType: Prefix
```

## Storage classes

The chart defaults to `rook-ceph-block` for both database and worker persistent volumes. Set `database.persistence.storageClass` and `worker.persistence.storageClass` to a storage class available in your cluster:

```bash
# List available storage classes
kubectl get storageclass
```

Then update your values file accordingly before installing or upgrading.

## Remove installation

```bash
helm uninstall enschedule --namespace enschedule
kubectl delete namespace enschedule
```

<Warning>
  Deleting the namespace removes all PersistentVolumeClaims, which may trigger deletion of the underlying PersistentVolumes depending on your reclaim policy. Back up your database before uninstalling.
</Warning>
