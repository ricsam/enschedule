You have two options for running Enschedule locally. Use **Docker Compose** for a fast local evaluation with no cluster required. Use **Helm** if you already have a Kubernetes cluster and want to evaluate Enschedule in that environment. Both options start PostgreSQL, a sample worker with pre-registered functions, and the dashboard — ready to use in a single command.

<Warning>
  These quickstarts use public alpha images and evaluation credentials. Do not expose either setup to an untrusted network. See [Deploy with Helm](/deployment/helm) for production-ready configuration.
</Warning>

<Tabs>
  <Tab title="Docker Compose">
    **Prerequisites:** Docker with Compose v2 (`docker compose version` should print `v2.x` or later).

    <Steps>
      <Step title="Download the Compose file">
        ```bash
        curl --fail --remote-name https://raw.githubusercontent.com/ricsam/enschedule/main/docker-compose.quickstart.yml
        ```
      </Step>
      <Step title="Start Enschedule">
        ```bash
        docker compose -f docker-compose.quickstart.yml up -d --wait
        ```

        Docker creates named volumes for PostgreSQL data and worker run logs. The `--wait` flag blocks until all services report healthy, so the dashboard is ready as soon as the command returns.
      </Step>
      <Step title="Open the dashboard">
        Go to [http://localhost:3000](http://localhost:3000) and sign in with:

        | Field | Value |
        | --- | --- |
        | Username | `adm1n` |
        | Password | `s3cr3t` |
      </Step>
    </Steps>

    **Inspect logs and tear down**

    Stream logs from all services:
    ```bash
    docker compose -f docker-compose.quickstart.yml logs -f
    ```

    Stop and remove containers (data volumes are preserved):
    ```bash
    docker compose -f docker-compose.quickstart.yml down
    ```

    Add `--volumes` only when you want to delete PostgreSQL data and run logs:
    ```bash
    docker compose -f docker-compose.quickstart.yml down --volumes
    ```
  </Tab>
  <Tab title="Helm">
    **Prerequisites:** A running Kubernetes cluster, Helm 3, and `kubectl` configured to point at it.

    <Steps>
      <Step title="Add the chart repository">
        ```bash
        helm repo add enschedule https://ricsam.github.io/enschedule
        helm repo update enschedule
        ```
      </Step>
      <Step title="Install Enschedule">
        ```bash
        helm upgrade --install enschedule enschedule/enschedule \
          --namespace enschedule \
          --create-namespace \
          --set database.persistence.enabled=false \
          --set worker.persistence.enabled=false \
          --set storage.enabled=false \
          --wait \
          --timeout 10m
        ```
      </Step>
      <Step title="Open the dashboard">
        Forward the dashboard service to your local machine:

        ```bash
        kubectl --namespace enschedule port-forward service/dashboard-service 3000:3000
        ```

        Go to [http://localhost:3000](http://localhost:3000) and sign in with:

        | Field | Value |
        | --- | --- |
        | Username | `adm1n` |
        | Password | `s3cr3t` |
      </Step>
    </Steps>

    **Remove the installation**

    ```bash
    helm uninstall enschedule --namespace enschedule
    kubectl delete namespace enschedule
    ```

    <Info>
      This quickstart disables persistent storage to minimize cluster requirements. For persistent volumes and production-ready values, continue to [Deploy with Helm](/deployment/helm).
    </Info>
  </Tab>
</Tabs>

## Run a sample function

Both installations register a **Log message** sample function that writes a payload field to the run log. Use it to verify the scheduler is working end to end:

1. Open **Functions** in the dashboard sidebar and select **Log message**.
2. Click **Create schedule**, enter the payload `{"message": "Hello from Enschedule"}`, and save.
3. Choose **Run now** to trigger an immediate execution.
4. Open the new run from the **Runs** list to inspect its status, timestamps, and captured log output.

<Check>
  Enschedule is running and your first scheduled function has completed. The run detail page shows a green status and the message you provided in the log output.
</Check>
