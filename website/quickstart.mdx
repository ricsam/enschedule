title: "Quickstart"

---

Choose Docker for a local evaluation or Helm for a Kubernetes cluster. Both options start PostgreSQL, a worker with sample functions, log storage, and the dashboard.

<Warning>
  These quickstarts use public alpha images and evaluation credentials. Do not expose either installation to an untrusted network. Follow the deployment guides before running Enschedule in production.
</Warning>

<Tabs>
  <Tab title="Docker Compose">

    ### Prerequisites

    Install [Docker](https://docs.docker.com/get-docker/) with Docker Compose v2.

    <Steps>
      <Step title="Download the Compose file">

        ```bash
        curl --fail --remote-name \
          https://raw.githubusercontent.com/ricsam/enschedule/main/docker-compose.quickstart.yml
        ```

      </Step>
      <Step title="Start Enschedule">

        ```bash
        docker compose -f docker-compose.quickstart.yml up -d --wait
        ```

        Docker creates named volumes for PostgreSQL data and run logs.

      </Step>
      <Step title="Open the dashboard">

        Open [http://localhost:3000](http://localhost:3000) and log in with:

        - Username: `adm1n`
        - Password: `s3cr3t`

      </Step>
    </Steps>

    To inspect or remove the stack:

    ```bash
    docker compose -f docker-compose.quickstart.yml logs -f
    docker compose -f docker-compose.quickstart.yml down
    ```

    Add `--volumes` to the `down` command only when you also want to delete the PostgreSQL data and run logs.

  </Tab>
  <Tab title="Helm">

    ### Prerequisites

    You need:

    - A Kubernetes cluster
    - [Helm 3](https://helm.sh/docs/intro/install/)
    - `kubectl` configured for that cluster

    <Steps>
      <Step title="Add the chart repository">

        ```bash
        helm repo add enschedule https://ricsam.github.io/enschedule
        helm repo update enschedule
        ```

        Browse available chart versions at [ricsam.github.io/enschedule](https://ricsam.github.io/enschedule/).

      </Step>
      <Step title="Install Enschedule">

        This evaluation install uses ephemeral PostgreSQL and log storage so it works without selecting a cluster-specific storage class:

        ```bash
        helm upgrade --install enschedule enschedule/enschedule \
          --namespace enschedule \
          --create-namespace \
          --set database.persistence.enabled=false \
          --set worker.persistence.enabled=false \
          --set storage.enabled=false \
          --wait \
          --timeout 10m
        ```

      </Step>
      <Step title="Open the dashboard">

        Forward the dashboard Service in a terminal:

        ```bash
        kubectl --namespace enschedule \
          port-forward service/dashboard-service 3000:3000
        ```

        Open [http://localhost:3000](http://localhost:3000) and log in as `adm1n` with password `s3cr3t`.

      </Step>
    </Steps>

    Remove the evaluation installation with:

    ```bash
    helm uninstall enschedule --namespace enschedule
    kubectl delete namespace enschedule
    ```

    For persistent storage, ingress, secret management, and production values, continue to [Deploy with Helm](/deployment/helm).

  </Tab>
</Tabs>

## Run a sample function

Both installations register a **Log message** sample function.

1. Open **Functions** and select **Log message**.
2. Create a schedule with a title and this payload:

   ```json
   {
     "message": "Hello from Enschedule"
   }
   ```

3. Choose **Run now**.
4. Open the new run to inspect its status and captured output.

<Check>
  Enschedule is running and your first scheduled function has completed.
</Check>
