Docker Compose is the simplest way to run the full Enschedule stack on a single host. The provided Compose file starts PostgreSQL, a worker with sample functions, log storage, and the React dashboard.

## Prerequisites

- Docker Engine with Compose v2 — use `docker compose` (not the legacy `docker-compose` plugin)

## Quickstart evaluation

<Warning>
  The quickstart file uses public alpha images and evaluation credentials. Do not expose this setup to an untrusted network.
</Warning>

Download the quickstart Compose file and bring the stack up:

```bash
curl --fail --remote-name \
  https://raw.githubusercontent.com/ricsam/enschedule/main/docker-compose.quickstart.yml
docker compose -f docker-compose.quickstart.yml up -d --wait
```

Open [http://localhost:3000](http://localhost:3000) and log in with username `adm1n` and password `s3cr3t`.

## Production Compose file

For a production deployment, set strong secrets via a `.env` file or your host's secrets manager, then reference them in your Compose file. The key environment variables are:

- `PG_PASSWORD` — the PostgreSQL superuser password
- `ACCESS_TOKEN_SECRET` / `REFRESH_TOKEN_SECRET` — secrets used to sign JWT tokens
- `API_KEY` — shared key between the dashboard and the worker's internal API
- `COOKIE_SESSION_SECRET` — secret used to sign the dashboard session cookie

```yaml docker-compose.yml
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${PG_PASSWORD}
      POSTGRES_DB: enschedule
    volumes:
      - pgdata:/var/lib/postgresql/data

  worker:
    image: ghcr.io/ricsam/enschedule-worker:latest
    depends_on: [postgres]
    environment:
      DATABASE_URL: postgres://postgres:${PG_PASSWORD}@postgres:5432/enschedule
      ENSCHEDULE_WORKER_ID: worker-1
      ENSCHEDULE_WORKER_NAME: Worker 1
      ENSCHEDULE_FUNCTIONS: /app/functions.js
      ENSCHEDULE_ACCESS_TOKEN_SECRET: ${ACCESS_TOKEN_SECRET}
      ENSCHEDULE_REFRESH_TOKEN_SECRET: ${REFRESH_TOKEN_SECRET}
      ENSCHEDULE_API: true
      ENSCHEDULE_API_KEY: ${API_KEY}
      NAFS_URI: file:///var/log/enschedule
      ENSCHEDULE_MIGRATE: true
    volumes:
      - runlogs:/var/log/enschedule
      - ./functions.js:/app/functions.js:ro

  dashboard:
    image: ghcr.io/ricsam/enschedule-dashboard:latest
    depends_on: [worker]
    ports:
      - "3000:3000"
    environment:
      ENSCHEDULE_WORKER_URL: http://worker:8000
      ENSCHEDULE_API_KEY: ${API_KEY}
      ENSCHEDULE_COOKIE_SESSION_SECRET: ${COOKIE_SESSION_SECRET}
      ENSCHEDULE_HTTPS_ONLY_COOKIES: "true"
      NODE_ENV: production

volumes:
  pgdata:
  runlogs:
```

<Note>
  Store secrets in a `.env` file at the same directory as your `docker-compose.yml` and exclude it from version control, or use your host's secrets manager (e.g. Docker Swarm secrets, HashiCorp Vault).
</Note>

## Mount your functions

The worker loads function modules via the `ENSCHEDULE_FUNCTIONS` environment variable. Mount your compiled ESM `.js` file into the container and set the variable to its in-container path:

```yaml
volumes:
  - ./functions.js:/app/functions.js:ro
environment:
  ENSCHEDULE_FUNCTIONS: /app/functions.js
```

To load multiple modules, separate their paths with spaces or commas:

```yaml
ENSCHEDULE_FUNCTIONS: /app/functions.js,/app/extra.js
```

Each module must export a default async `register` function that receives the worker instance:

```ts
export default async function register(worker) {
  worker.registerFunction({
    id: "my-job",
    title: "My job",
    run: async (payload, logger) => {
      logger.log("Running with payload:", payload);
    },
  });
}
```

## Run database migration

Set `ENSCHEDULE_MIGRATE=true` on the worker service to run migrations automatically on startup. In production you may prefer to run the migration as a separate step before deploying new images:

```bash
docker run --rm \
  -e DATABASE_URL=postgres://user:password@host:5432/enschedule \
  ghcr.io/ricsam/enschedule-worker:latest \
  bun packages/pg-driver/migrate.ts
```

<Warning>
  Back up your database before running migrations. See the [upgrade guide](/deployment/upgrades) for the recommended pre-upgrade checklist.
</Warning>

## Inspect and manage

Use standard `docker compose` commands to operate your stack:

```bash
# Follow logs for all services
docker compose logs -f

# Restart a single service
docker compose restart worker

# Stop everything while keeping volumes intact
docker compose down

# Stop and permanently delete all data volumes
docker compose down --volumes
```
