Enschedule serves a JSON HTTP API generated from a shared Richie RPC contract.

## Base paths

| Resource | Path |
| --- | --- |
| API | `/api` |
| API health | `/api/healthz` |
| Dashboard health | `/healthz` |
| OpenAPI 3.1 document | `/openapi.json` |
| Built-in Scalar reference | `/docs` |

The API reference in this site is generated from the same contract.

## Check health

```bash
curl https://enschedule.example.com/api/healthz
```

```json
{
  "message": "Endpoint is healthy",
  "runtime": "bun"
}
```

## Send JSON requests

```bash
curl --request GET \
  --url https://enschedule.example.com/api/schedules \
  --header 'X-API-Key: your-api-key'
```

Request and response bodies use JSON. Streaming run logs use the Richie RPC streaming transport.

## Error shape

Standard API errors use this form:

```json
{
  "code": "NOT_FOUND",
  "message": "Schedule not found",
  "issues": []
}
```

`issues` is optional. Common response statuses include `400`, `401`, `403`, `404`, `409`, and `500`.

## OpenAPI document

Use **Download API spec** in the page menu, or fetch `/openapi.json` from a running Enschedule dashboard. The checked-in `openapi.json` document is OpenAPI 3.1 and is generated from `packages/types/contract.ts`.
