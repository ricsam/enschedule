Workers register themselves in PostgreSQL when they start. Use the workers API to see which workers are currently registered, their reported status, and the function IDs and versions they expose.

## List workers — `GET /api/workers`

```bash
curl https://enschedule.example.com/api/workers \
  --header 'X-API-Key: your-api-key'
```

Returns an array of worker objects.

### Response fields

<ResponseField name="workerId" type="string">
  The stable identifier for the worker class. Shared across all running instances of the same worker.
</ResponseField>

<ResponseField name="instanceId" type="string">
  A unique ID for this specific running process. Changes each time the process restarts.
</ResponseField>

<ResponseField name="name" type="string">
  The human-readable display name for the worker.
</ResponseField>

<ResponseField name="status" type="string">
  The current worker status: `UP`, `PENDING`, or `DOWN`.
</ResponseField>

<ResponseField name="lastSeenAt" type="string">
  ISO 8601 timestamp of the most recent heartbeat received from this worker.
</ResponseField>

<ResponseField name="definitions" type="array">
  The list of function definitions this worker has registered, each containing a `functionId` and `functionVersion`.
</ResponseField>

## Worker statuses

| Status | Meaning |
| --- | --- |
| `UP` | Checked in within its normal polling window |
| `PENDING` | Missed its normal interval but not yet timed out |
| `DOWN` | Has not checked in before the down threshold |
