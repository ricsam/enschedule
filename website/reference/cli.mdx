The `enschedule` CLI manages schedules through the Enschedule API. Set three environment variables before using any command.

## Configure the CLI

```bash
export ENSCHEDULE_API_ENDPOINT=https://enschedule.example.com
export ENSCHEDULE_API_KEY=your-api-key
export ENSCHEDULE_API_VERSION=1
```

<Note>
The CLI's configuration version is `1`; the supported HTTP base path is still `/api`, not `/api/v1`.
</Note>

## Apply declarative schedules

`enschedule apply` creates or updates schedules from YAML or JSON files. The `metadata.name` field becomes the schedule `eventId`, so re-running apply updates the existing schedule rather than creating a duplicate.

```bash
enschedule apply --file schedules/
```

The `--file` argument accepts a single file path, a glob pattern, or a directory. When you pass a directory, `apply` loads all `.yaml`, `.yml`, and `.json` files it finds inside.

```yaml title="schedules/weekday-report.yaml"
apiVersion: v1
kind: schedule
metadata:
  name: weekday-report
spec:
  functionId: build-report
  functionVersion: 1
  data:
    accountId: acct_123
  options:
    title: Weekday report
    description: Build the report every weekday morning
    cronExpression: "0 9 * * 1-5"
```

## create schedule

```bash
enschedule create schedule \
  --name receipt-ord-123 \
  --function-id send-receipt \
  --function-version 1 \
  --title 'Send receipt' \
  --data '{"orderId":"ord_123","email":"customer@example.com"}' \
  --run-now
```

<Note>
Use `--update` to replace a schedule that already exists with the same stable name.
</Note>

## get schedules / get schedule

```bash
# List all schedules
enschedule get schedules
enschedule get schedules --output wide
enschedule get schedules --output json

# Get one schedule (event ID or db: prefix for numeric ID)
enschedule get schedule weekday-report
enschedule get schedule db:42 --output json
```

## update schedule

```bash
enschedule update schedule weekday-report \
  --title 'Updated weekday report' \
  --run-now
```

## delete schedule

```bash
enschedule delete schedule weekday-report db:42
```

You can delete multiple schedules in one command by listing their names or `db:ID` values as separate arguments.

## Common flags

| Flag | Description |
| --- | --- |
| `--name` | Schedule `eventId` / stable name |
| `--function-id` | Target function ID |
| `--function-version` | Target function version |
| `--title` | Schedule display title |
| `--data` | JSON-encoded payload |
| `--cron` | Cron expression for recurring schedules |
| `--run-now` | Trigger an immediate run |
| `--run-at` | ISO 8601 timestamp for a one-time run |
| `--update` | Update existing schedule with same name |
| `--output` | Output format: `table`, `wide`, `json` |
| `--file` | Path, glob, or directory for `apply` |
