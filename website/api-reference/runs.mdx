Runs are created automatically whenever a schedule is claimed and executed. Use the runs API to retrieve status, timing, and captured output for any execution attempt.

## List runs — `GET /api/runs`

```bash
curl https://enschedule.example.com/api/runs \
  --header 'X-API-Key: your-api-key'
```

Returns an object with a `count` of total matching runs and a `rows` array of run objects. Supports `scheduleId`, `order`, `limit`, and `offset` query parameters for filtering and pagination.

## Get a run — `GET /api/runs/:id`

```bash
curl https://enschedule.example.com/api/runs/42 \
  --header 'X-API-Key: your-api-key'
```

### Response fields

<ResponseField name="id" type="number">
  The unique run ID.
</ResponseField>

<ResponseField name="status" type="string">
  The current run status: `RUNNING`, `SUCCESS`, `FAILED`, or `LOST`.
</ResponseField>

<ResponseField name="startedAt" type="string | null">
  ISO 8601 timestamp of when the worker began executing the run, or `null` if not yet started.
</ResponseField>

<ResponseField name="finishedAt" type="string | null">
  ISO 8601 timestamp of when the run completed, or `null` if the run is still in progress.
</ResponseField>

<ResponseField name="scheduledToRunAt" type="string | null">
  ISO 8601 timestamp of when the run was originally scheduled to execute.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp of when this run record was created.
</ResponseField>

<ResponseField name="exitSignal" type="string">
  The exit signal or error code captured when the run ended, if applicable.
</ResponseField>

<ResponseField name="data" type="string">
  The JSON payload (serialised as a string) that was passed to the function for this run.
</ResponseField>

## Run statuses

| Status | Meaning |
| --- | --- |
| `RUNNING` | Run has started, no finish timestamp yet |
| `SUCCESS` | Completed without error |
| `FAILED` | Threw an error or exited non-zero |
| `LOST` | No finish timestamp and worker is unavailable |
