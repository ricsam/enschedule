Enschedule serves a JSON HTTP API generated from a shared Richie RPC contract. All first-party clients — the dashboard, CLI, and worker — use this same API. The base path is `/api`.

## Base paths

| Resource | Path |
| --- | --- |
| API | `/api` |
| API health | `/api/healthz` |
| Dashboard health | `/healthz` |
| OpenAPI 3.1 document | `/openapi.json` |
| Built-in Scalar reference | `/docs` |

## Check health

```bash
curl https://enschedule.example.com/api/healthz
```

```json
{
  "message": "Endpoint is healthy",
  "runtime": "bun"
}
```

## Send requests

```bash
curl --request GET \
  --url https://enschedule.example.com/api/schedules \
  --header 'X-API-Key: your-api-key'
```

Request and response bodies use JSON. Include `Content-Type: application/json` on all POST and PUT requests.

## Error shape

Standard API errors use this form:

```json
{
  "code": "NOT_FOUND",
  "message": "Schedule not found",
  "issues": []
}
```

Common response codes:

| Code | Meaning |
| --- | --- |
| `400` | Bad request or validation error |
| `401` | Unauthenticated |
| `403` | Forbidden |
| `404` | Resource not found |
| `409` | Conflict (e.g. duplicate event ID) |
| `500` | Internal server error |
